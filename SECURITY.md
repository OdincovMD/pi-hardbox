# Секреты и границы управления

## Вне репозитория

- `/etc/hardbox-vpn/xray.json`: настоящая VLESS-подписка.
- `/etc/hardbox-vpn/wifi.json` и профиль NetworkManager: Wi-Fi-пароль.
- `/etc/hardbox-vpn/img2txt/xray.json`: производный ключ для контейнера.
- `/var/lib/hardbox-vpn`: последние рабочие конфиги, pending-маркеры,
  ручные доменные исключения, DHCP leases и диагностика.
- `/etc/shadow`, сессионные cookies и пароли владельца.
- `service/.env` отдельного img2txt: LLM и сервисные токены.
- Архивы установки, staging-каталоги, дампы, журналы и резервные копии.

Публичные HTTP-ответы не возвращают ключи, пароли, ручные доменные списки,
IP/MAC клиентов или полные данные Docker inspect. Права конфигов:
основные файлы 0600/root, производный img2txt 0640/root:65532 в каталоге 0700.

## Источники и примеры

`gateway/templates/xray.example.json` содержит только демонстрационный endpoint,
нулевой UUID и демонстрационный public key. Его нельзя использовать как
рабочую подписку. Генератор запрашивает настоящие значения через getpass,
пишет их в отдельный закрытый каталог и отказывается писать внутри checkout.

`tools/check_publication.py` проверяет имена файлов, типичные форматы ключей,
содержимое Git index и всю достижимую историю. Подготовка этого снимка также
проверяется на точные значения реально установленных секретов в памяти root
на сервере; эти значения не передаются в репозиторий или журналы проверки.
После клонирования включите hook из `.githooks` согласно PUBLISHING.md.

## Управление

Авторизация владельца использует PAM и ограниченную по времени HttpOnly-сессию.
Сайт работает без root; отдельные контроллеры принимают фиксированные команды
по Unix-сокетам. Подтверждение reboot проверяется отдельно. Тестовые fixture-ключи
и подмены PAM не устанавливаются в рабочую PAM-конфигурацию.
